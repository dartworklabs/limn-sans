# 한글 먹·점 수·파일 크기 실험 — 2026-10-18

비공개 이력의 한글 품질 과제(이슈 #30)에 대한 제한된 후속 조사다. 생산 글리프와 생성 규칙은 바꾸지 않는다.

## 판정

- 0.8은 정보 기준으로 유지한다. 현재 369건을 실패로 올리기에는 마스터 대체, 흰 틈 보존, 굵기 순서 보정이 겹친다. 규칙을 바꾼 시안과 읽기 검토가 더 필요하다.
- 이번 **세 후보 포트폴리오 정책은 채택하지 않는다.** SVG 감사 점 수는 8점 줄었지만, 실제 TTF 점 수와 TTF·WOFF2 크기가 늘었다. 현행 첫 통과 후보 정책을 유지한다.
- 전역 최소 탐색 전체를 기각한 결과는 아니다. 다시 실험할 때에는 SVG 점 수 대신 실제 글리프 직렬화 뒤의 점 수와 파일 크기를 목적 함수에 포함해야 한다.

## 입력과 재현 범위

먹 시트는 회수한 2026-10-01 생성물의 현대 한글 11,172자 × 9굵기를 그대로 읽는다. 낮은 먹 목록은 `audit_hangul.py`와 같은 곡선 평탄화·짝홀 채움·소수 한 자리 면적을 사용한다. 느린 속공간 내접원 계산만 생략하며, 실제 글리프 5건에서 전체 `measure()`와 면적이 정확히 같았다. 점수는 `(Limn 글자 먹 / Limn 가 먹) / (해당 굵기 명목 부모 글자 먹 / 부모 가 먹)`이다. 토폴로지 때문에 실제 선택한 부모가 달라도 기존 감사와 같은 명목 부모를 분모로 쓴다.

점·크기 실험은 `가굶쬡똴쫠헬쪽헤를훑갂훻` 12자 × 9굵기다. 마지막 두 글자는 부모가 직접 그리지 않은 합성 음절이다. 회수 JS의 `pair` 값을 고정하고, 현행 빌더가 최종 채택한 맞춤 전 도형과 힌트를 메모리에서 포착했다. 두 정책은 그 도형을 공유한다. 생산 파일이나 빌더 함수의 파일 내용은 바꾸지 않았다.

**재생성 기준선은 역사적 생성물의 재현이라고 주장하지 않는다.** JS의 pairing은 소수 넷째 자리까지만 있고, 회수 생성물의 전체 정밀도·dirty source·의존성 이력도 완전히 복구되지 않았다. 실험 기준선과 회수 데이터의 윤곽 문자열은 108건 중 12건만 같다. 회수 데이터의 같은 표본 SVG 감사 점 수는 17,442점, 실험 재생성 기준선은 17,238점이다. 따라서 후보와의 차이는 동일 입력에서 재생성한 두 정책 사이의 결과로만 해석한다. 새 캐시를 끈 원본 HEAD 빌드에서도 회수 데이터와 pairing이 다른 현상은 재현되어, 이 차이를 새 캐시의 회귀로 돌릴 근거는 없다.

새 `review_hangul_quality.py`는 입력 JS 18개, 부모 TTF 4개, 관련 소스의 SHA-256과 Python·의존성 버전을 JSON에 남긴다. 시트 HTML은 외부 폰트·스크립트·네트워크 자원 없이 열린다. 모든 글자와 부모는 동일한 1000 UPM 좌표·배율·기준선을 쓰며, 부모에는 명목 pairing의 배율과 위치만 적용한다. 글자마다 크기를 다시 맞추지 않는다.

## 점 수와 실제 파일 크기

정책은 첫 통과 기준선을 보존한 채 기존의 보통 후보 세 개를 모두 계산하고 `(SVG 감사 점 수, SVG 문자열 길이)`가 가장 작은 결과를 고른다. 비싼 smoothing fallback은 기준선으로만 보존한다. `fit_checked(max_points=...)`는 예산 안의 **첫** 후보를 돌려주며 전역 최소 탐색이 아니다. 이번 정책도 정해진 후보 집합 안의 최소일 뿐이다.

다음 파일은 12글자와 `.notdef`만 담은 **힌팅 없는 실측 표본 폰트**다. 두 정책 모두 생산 `build_ttf.outline(..., implied=True)` 변환을 사용하고, 고정한 동일 이름·시간·메트릭으로 직렬화했다. 릴리스 전체 TTF나 웹 core WOFF2의 크기로 외삽하지 않는다.

SVG 감사 점 수는 17,238→17,230으로 8점(0.046%) 줄었다. 그러나 900 훻은 SVG 488→486점인 반면 실제 TTF는 435→480점이었다. 독립 검토에서 생산 pathops simplify 이후 quadratic 구간이 239→277개로 증가하는 것을 확인했다. 원래 SVG의 암시적 on-curve 절감이 overlap 제거 뒤에도 보존되는 것은 아니다. 새 cubic 근사가 늘어난 경우는 아니다. 시트는 SVG 감사 점 수와 실제 TTF 점 수를 함께 표시한다.

실험에서 글자별로 잰 벽시계 시간의 합은 첫 통과 생성 733.13초, 추가 후보 비교 178.28초였다. 기준선을 보존하고 포트폴리오까지 비교하는 정책의 누적 글자 시간은 911.41초로 24.3% 늘었다. 두 단계를 합친 3프로세스 전체 실행 벽시계 시간은 372.85초다. 이 누적 값은 프로세스 병렬 실행의 전체 빌드 시간과 다르며, 전체 11,172자 빌드 시간으로 추정하지 않는다. 파일 직렬화와 후속 검증 시간은 이 값에 포함하지 않았다.

## 검증과 증거

- 실제 최종 선택 윤곽 양쪽 108건씩에서 토폴로지, 부모 토폴로지, counter/gap, specks/tiny/badring/semi, 곡선 출력, 굵기별 먹 증가, 고정 advance 및 `가`의 먹으로 정규화한 부모 먹 0.5 기준을 재검사했다. 모두 통과했고 가족 전체의 후보 기각은 0건이었다. 기각이 생기는 경우 시험 후보의 측정값 대신 실제 복귀한 기준선 윤곽을 사용한다.
- 출력 TTF 양쪽을 다시 열어 실제 곡선과 advance를 읽고 같은 표본 게이트를 재검사했다. 모두 통과했다. 출력 폰트 36개(9굵기 × 2정책 × TTF/WOFF2)의 점 수와 바이트 수도 독립 검토에서 확인했다.
- 회수 생성물 전체 11,279글자 × 9굵기의 기존 `make check`는 별도로 통과했다. 이 표본 실험을 전체 생산 후보 검증으로 간주하지 않는다.
- 새 도구 테스트 4개와 Ruff format/lint·mypy가 통과했다. 면적의 짝홀 채움, 생성 입력의 면적 일치 속성, 흰 틈 경계, 기준 글자 누락을 검사한다. XOR→union, 면적 +1, `<`→`<=`, 가 누락 검사 제거 변이를 각각 거부했다. `make quality`와 기존 테스트 탐색에 포함되며 CI 설정을 새로 바꾸지는 않았다.

운영 산출물은 저장소 밖의 작업 폴더에 둔다. 근거 파일은 `ink-sheet.{html,json}`, `benchmark.json`, `point-comparison.html`, `family-*.json`, `representative-measures.json`, `decoded-ttf-gates.json`, `sample-*.{ttf,woff2}`, 테스트·변이·quality 로그다. 검토 화면의 Tailnet 주소는 비공개 작업 보고에서 전달하고 이 문서에 고정하지 않는다.

저장소 루트에서 다음을 실행한다. `OUT`은 검토 산출물을 둘 저장소 밖의 폴더다. 기본 표본에 가가 포함되어 있으며, `--chars`로 바꿀 때에도 부모 먹 정규화를 위해 가를 포함해야 한다.

```sh
uv run --no-project --with fonttools --with skia-pathops --with numpy --with shapely \
  --with scipy --with brotli python3 site/tools/review_hangul_quality.py sheet --out "$OUT"
uv run --no-project --with fonttools --with skia-pathops --with numpy --with shapely \
  --with scipy --with brotli python3 site/tools/review_hangul_quality.py benchmark --out "$OUT"
make quality
```

현재 #22의 정확 입력 캐시는 같은 입력 재실행을 재사용한다. 생산 코드가 달라져도 동일 도형의 곡선 맞춤을 재사용하는 단계는 아직 없으므로, 이번 결과를 전체 생산 최적화를 빠르게 반복할 수 있게 됐다는 근거로 쓰지 않는다. 재시도 조건은 실제 직렬화 비용을 최적화하는 후보 정책, 원본 생성 이력 정리, 더 넓은 표본 및 변경 시안의 사용자 검토다.
